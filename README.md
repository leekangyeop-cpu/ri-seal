# ri-seal — AI 에이전트 작업 영수증 · 봉인 · 검증

[English](README.en.md)

AI 에이전트(Claude Code 등)가 **언제 어떤 파일을 고쳤는지** 영수증처럼 기록합니다. 하루에 한 번 그 기록에 **회사 전용 디지털 도장**을 찍습니다. **도장을 찍은 뒤에** 누군가 그 이전 기록을 몰래 고치거나 지우면 드러납니다(아래 '한계와 전제' 참고).

> 루트인사이드 주식회사가 자사 시스템에 적용한 봉인 방식을 누구나 쓸 수 있게 떼어 낸 무료 도구입니다(사내 가동 2026-10-01 시작).

## 무엇이 좋은가
- **봉인된 기록은 지워도 드러납니다.** 영수증은 줄마다 앞줄의 지문을 품고 있어서, 봉인 이전 기록이 한 줄만 빠지거나 바뀌어도 맞지 않게 됩니다.
- **내용은 저장하지 않습니다.** 파일 내용이나 명령어는 남기지 않고 지문(SHA-256)만 남깁니다.
- **내 컴퓨터에서만 돕니다.** 서버도, 사용 통계 수집도 없습니다. `anchor` 명령을 직접 실행할 때만 봉인 지문(32바이트)과 타임스탬프 요청용 임의 난수가 외부로 나갑니다(내용·파일명 없음).
- **에이전트를 멈추지 않습니다.** 기록 중 오류가 나도 에이전트 작업은 그대로 진행됩니다.
- **제3자가 우리 없이 검증합니다.** 서명(in-toto·DSSE)과 시각 증명(OpenTimestamps·RFC 3161)은 공개 표준 도구로, 영수증·봉인의 해시 사슬은 ri-seal 로 검증합니다.

## 3분 시작
```bash
pip install "ri-seal[anchor] @ git+https://github.com/leekangyeop-cpu/ri-seal"   # PyPI 에는 아직 없습니다 — GitHub 에서 직접 설치
cd 내-프로젝트
ri-seal init                  # 도장(서명 키) 만들기 — 키는 프로젝트 밖 ~/.riseal/keys 에 저장
ri-seal install-claude-hook   # Claude Code 가 작업할 때마다 영수증 자동 기록(기본: 내 로컬 설정, 팀 공유 설정은 --shared)
```
이제 평소처럼 에이전트에게 일을 시키면 됩니다. 하루 일이 끝나면:
```bash
ri-seal seal 보고서.pdf        # 오늘 영수증 + 보고서에 도장
ri-seal anchor                # (선택) 비트코인·타임스탬프 기관에 시각 고정 — 지문만 전송
ri-seal verify                # 누가 고쳤는지 전체 점검
```
다른 사람에게 증명할 때:
```bash
ri-seal export 증빙.zip       # 공개키·영수증·도장·시각 증명 + 검증 안내서
```

## 보안 기록이 남지 않도록 — 무엇을 기록하고 무엇을 절대 기록하지 않는가
| 절대 기록하지 않음 | 파일 내용, 명령어 원문, 도구 출력, 비밀키 |
| --- | --- |
| **이름도 숨김**(HMAC만) | `.env`, `*.pem`, `*.key`, `*secret*`, `*token*`, `*password*`, `.ssh/`, `.aws/` 등 기본 목록 + 직접 지정한 `.risealignore` 패턴. 이런 파일은 내용 지문도 남기지 않음 |
| **열쇠가 있어야만 대조 가능** | 명령어·세션은 일반 해시가 아니라 비밀 키(pepper)로 만든 HMAC — 짧은 비밀번호도 추측으로 알아낼 수 없음 |
| **그대로 기록** | 민감하지 않은 프로젝트 안 파일 경로와 그 지문(SHA-256) |

- `ri-seal init --privacy strict` 로 시작하면 영수증과 봉인의 **모든 경로 이름**을 HMAC 으로만 남깁니다(고객사·기밀 프로젝트 권장).
- 봉인할 때 비밀처럼 보이는 파일은 자동으로 빠지고 알려 줍니다(`--allow-sensitive` 로만 포함).
- 기록 폴더 `.riseal/` 는 본인만 읽을 수 있게(700) 만들어지고 영수증·봉인 파일은 600 입니다(설정·공개키 같은 비밀 아닌 파일은 644). 서명 키와 pepper 는 프로젝트 밖 `~/.riseal/keys/` 에 0600 으로 둡니다.
- 외부로 나가는 것은 `anchor` 를 직접 실행할 때의 봉인 지문 32바이트와 임의 난수뿐입니다(요청을 보내는 쪽의 IP는 어떤 인터넷 요청이든 서버에 남습니다).

## 한계와 전제(꼭 읽어 주세요)
- **봉인하지 않은 최근 기록은 보호되지 않습니다.** 마지막 봉인 이후의 영수증은 지워도 드러나지 않습니다. 하루 1번 이상 `seal` 하세요.
- **봉인 행 자체를 꼬리에서 잘라내는 것은 로컬 `verify` 가 못 잡습니다**(키가 없어도 가능). 밖에 둔 `export` 사본의 봉인 수와 비교하거나 `verify --expect-seals N` 으로 확인해야 드러납니다.
- **앵커 행은 서명되지 않습니다.** `verify` 는 영수증이 '이 봉인에 대한 것'인지만 확인하고, 진위는 `ots verify`·`openssl ts -verify` 로 따로 확인합니다.
- **에이전트도 같은 사용자 권한으로 돕니다.** 에이전트가 마음먹으면 `~/.riseal/keys` 의 키를 읽어 기록과 도장을 통째로 다시 만들 수 있습니다. 아래 세 가지는 그 위험을 **줄이는** 장치이지 완전히 막는 장치가 아닙니다.
  1. **`ri-seal anchor` 를 매일 실행하고, 2번과 함께** — 비트코인·타임스탬프 기관의 시각 증명은 키가 있어도 과거로 다시 만들 수 없습니다. 다만 증명 파일이 같은 컴퓨터에 있으면 함께 지워질 수 있으므로 외부 사본과 함께해야 효과가 있습니다.
  2. **`export` 묶음을 에이전트가 닿지 않는 곳(다른 기기·메일)에 보관** — 나중에 다시 만든 기록과 비교됩니다.
  3. **에이전트가 키 폴더를 읽지 못하게 설정** — Claude Code 라면 프로젝트 설정의 `permissions.deny` 에 `Read(~/.riseal/**)` 등을 추가하세요. 설정은 우회 가능성이 있어 보조 장치입니다.
- **제3자는 공개키 지문을 따로 확인해야 합니다.** `verify` 가 출력하는 `pubkey_sha256` 을 발행자가 자기 웹사이트·GitHub 에 올린 값과 비교해야 위조 묶음을 걸러냅니다.
- macOS·Linux 전용입니다(Windows 미지원).

## 꼭 알아 둘 것
- **도장(개인키)을 백업하세요.** `~/.riseal/keys/` 의 파일을 암호화 USB나 비밀번호 관리자에 한 부 보관하세요. 잃어버려도 과거 도장은 공개키로 계속 검증됩니다.
- **공개키 지문을 공개하세요.** `ri-seal init` 이 보여 주는 `pubkey_sha256` 을 회사 웹사이트·GitHub 등 두 곳 이상에 올리면, 남이 가짜 도장을 만들어도 구별됩니다.
- **도장은 '그때 이 상태였다'를 증명할 뿐**, 기록 내용이 옳다는 것을 증명하지 않습니다.
- 이 도구는 인증 서비스나 법률 자문이 아닙니다. 법적 증명력이 필요하면 공인전자문서센터 등 공인 기관을 함께 쓰세요.

## 명령 요약
| 명령 | 하는 일 |
| --- | --- |
| `ri-seal init` | `.riseal/` 생성, 서명 키 생성(프로젝트 밖) |
| `ri-seal install-claude-hook [--shared]` | 로컬 설정(`settings.local.json`, 기본)에 기록 훅 추가 — `--shared` 는 팀 공유 `settings.json` 에 경로 없는 `ri-seal hook` 으로. 처음 원본은 `.bak` 보관 |
| `ri-seal hook` | 에이전트가 부르는 기록 명령 — 직접 쓸 일 없음 |
| `ri-seal seal [파일·폴더…]` | 지금까지의 영수증 + 지정한 파일에 서명 |
| `ri-seal anchor` | (선택) OpenTimestamps 2곳 + RFC 3161 기관 1곳에 시각 고정 |
| `ri-seal verify [--expect-seals N]` | 영수증·도장·서명·공개키 지문·파일 변경 점검, 앵커는 대상 일치만(진위는 외부 도구). 종료 코드 0=깨끗, 2=사슬은 멀쩡하나 봉인 뒤 파일이 바뀜, 1=사슬·서명 문제 |
| `ri-seal export 파일.zip` | 제3자 검증용 묶음(개인키 제외) |

## 루트인사이드 공개키 지문(대역외 대조용)
루트인사이드 자사 봉인(https://www.rootinsidegroup.com/trust)의 Ed25519 공개키 지문 — 웹사이트에 적힌 값과 **이 저장소의 값이 같아야** 합니다(둘 중 하나가 바뀌면 키가 교체·변조된 것).
```
sha256(raw 32-byte key) = 29b8c0462adbc700b147b634e18021fb58e34478272be5a56547d7aa4e7889d8
```
확인: `openssl base64 -d -in pubkey.pem | tail -c 32 | shasum -a 256` (macOS LibreSSL·Linux OpenSSL 공통).
