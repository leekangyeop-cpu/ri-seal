# ri-seal — AI 에이전트 작업 영수증 · 봉인 · 검증

[English](README.en.md) · [면책](DISCLAIMER.md) · [개인정보](PRIVACY.md) · [보안](SECURITY.md) · [기여](CONTRIBUTING.md) · [변경 기록](CHANGELOG.md)

AI 에이전트(Claude Code 등)가 **언제 어떤 파일을 고쳤는지** 영수증처럼 기록합니다. 하루에 한 번 그 기록에 **회사 전용 디지털 도장**을 찍습니다. **도장을 찍은 뒤에** 누군가 그 이전 기록을 몰래 고치거나 지우면 드러납니다(아래 '한계와 전제' 참고).

0.2(개인판)부터는 **한 화면**에서 오늘 내 에이전트가 무엇을 했고 그 말이 영수증과 맞았는지를 봅니다 — 보안·효율·정확성 세 기둥(`ri-seal status`, 브라우저로는 `ri-seal ui`).

> 루트인사이드 주식회사가 자사 시스템에 적용한 봉인 방식을 누구나 쓸 수 있게 떼어 낸 무료 도구입니다(사내 가동 2026-10-01 시작).

## 무엇이 좋은가
- **봉인된 기록은 지워도 드러납니다.** 영수증은 줄마다 앞줄의 지문을 품고 있어서, 봉인 이전 기록이 한 줄만 빠지거나 바뀌어도 맞지 않게 됩니다.
- **내용은 저장하지 않습니다.** 파일 내용이나 명령어는 남기지 않고 지문만 남깁니다. 기본값(strict)에서는 경로 이름도 HMAC 으로만 남깁니다.
- **내 컴퓨터에서만 돕니다.** 서버도, 사용 통계 수집도 없습니다. `anchor` 명령을 직접 실행할 때만 봉인 지문(32바이트)과 타임스탬프 요청용 임의 난수가 외부로 나갑니다(내용·파일명 없음). 자세히: [PRIVACY.md](PRIVACY.md)
- **에이전트를 멈추지 않습니다.** 기록 중 오류가 나도 에이전트 작업은 그대로 진행됩니다.
- **제3자가 우리 없이 검증합니다.** 서명(in-toto·DSSE)과 시각 증명(OpenTimestamps·RFC 3161)은 공개 표준 도구로, 영수증·봉인의 해시 사슬은 ri-seal 로 검증합니다.

## 이 도구가 보장하지 않는 것(설치 전에 읽어 주세요)
- 봉인과 외부 시각 고정은 기록이 그 시점에 그 상태였고 그 뒤 바뀌지 않았음을 보여 주는 기술적 증거입니다. 공인전자서명·공인 시점확인·공증·인증 서비스가 아니며 내용의 진위·성과·완전성·법적 효력을 보증하지 않습니다.
- `status` 의 숫자와 주장 대조는 이 컴퓨터의 기록 파일을 센 값입니다. 작업의 품질이나 성과를 평가하지 않습니다.
- 마지막 봉인 이후의 기록, 같은 사용자 권한으로 키에 닿는 에이전트의 재작성은 막지 못합니다(아래 '한계와 전제').
- 투자 권유나 투자·법률 조언이 아닙니다. 무상·현 상태(AS IS) 제공이며 자세한 고지는 [DISCLAIMER.md](DISCLAIMER.md) 에 있습니다.

## 3분 시작
```bash
# 1) 설치 — 커밋을 고정해서 설치하세요. <COMMIT> 자리에 GitHub 릴리스 페이지에 적힌 40자리 커밋 해시를 넣습니다.
#    (브랜치 이름으로 설치하면 저장소가 바뀔 때 다른 코드가 설치될 수 있습니다 — SECURITY.md 5절)
pip install "ri-seal[anchor] @ git+https://github.com/leekangyeop-cpu/ri-seal@<COMMIT>"
# 또는 릴리스 태그로(태그는 옮겨질 수 있어 커밋 고정이 더 단단합니다):
# pip install "ri-seal[anchor] @ git+https://github.com/leekangyeop-cpu/ri-seal@v0.2.0"
# 또는 릴리스의 wheel 을 받아 shasum -a 256 -c SHA256SUMS 로 확인한 뒤 pip install <wheel 파일>

# 2) 시작
cd 내-프로젝트
ri-seal init                  # 도장(서명 키) 만들기 — 키는 프로젝트 밖 ~/.riseal/keys. 기본은 strict(경로 이름 전부 숨김)
ri-seal install-claude-hook   # 바뀔 내용을 먼저 보여 주고 훅 2개를 등록합니다:
                              #   PostToolUse → 영수증 자동 기록 / Stop → 주장↔영수증 대조(측정만, 차단 0)
                              #   주장 대조를 빼려면 --no-claim-hook, 미리보기만 보려면 --dry-run
```
이제 평소처럼 에이전트에게 일을 시키면 됩니다. 언제든:
```bash
ri-seal status                # 세 기둥 화면(한국어: --lang ko, 영어: --lang en)
ri-seal status --details      # 숫자마다 근거 파일:줄 번호
ri-seal ui                    # 같은 화면을 브라우저로 — http://127.0.0.1:8765 (이 컴퓨터에서만, Ctrl+C 로 종료)
```
하루 일이 끝나면:
```bash
ri-seal seal 보고서.pdf        # 오늘 영수증 + 보고서에 도장
ri-seal anchor                # (선택) 비트코인·타임스탬프 기관에 시각 고정 — 지문만 전송
ri-seal verify                # 누가 고쳤는지 전체 점검(결과는 status 의 '마지막 verify' 에 표시)
```
다른 사람에게 보여 줄 때:
```bash
ri-seal export 증빙.zip       # 공개키·영수증·도장·시각 증명 + 검증 안내서
```
그만 쓸 때:
```bash
ri-seal uninstall-claude-hook # 설치한 훅 두 항목만 정확히 제거(다른 훅은 그대로), 바뀔 내용을 먼저 보여 줌
```

## 세 기둥 화면(`status` · `ui`)
맨 위에 세 문장(기둥마다 한 문장), 그 아래 숫자, 맨 아래 고정 문장 — "이 표시는 기록의 상태를 보여 주며 내용의 옳고 그름이나 성과를 보증하지 않습니다".

| 기둥 | 숫자 | 어디서 세나 |
| --- | --- | --- |
| 보안 | 오늘 영수증 수 · 이름 숨김(HMAC) 수 · 봉인 수 · 마지막 봉인 시각 · 시각 고정 상태(none/pending/complete) · 마지막 verify 결과 · 훅 오류 | `.riseal/receipts.jsonl` · `seals.jsonl` · `verify_log.jsonl` · `hook_errors.log` |
| 효율 | 오늘 편집한 파일 수 · 같은 파일을 3번 이상 고친 수(재작업) · 세션 수 | `receipts.jsonl` 의 Edit/Write 행 |
| 정확성 | 주장 적중률 = supported ÷ (supported + unsupported), 최근 30일. unknown 은 분모에서 빼고 따로, 분모 30 미만이면 `small_n` | `.riseal/claims.jsonl` |

- 색은 셋입니다: 초록 '이상 없음', 노랑 '미완료'(시각 고정 대기·verify 안 함·재작업 있음·small_n), 빨강 '확인 필요'(verify 실패·오늘 근거 없는 주장). **품질 점수가 아니라 기록 상태 표시**입니다.
- 시각 고정 `complete` 는 모든 봉인에 OpenTimestamps 와 RFC 3161 영수증이 **있다**는 뜻입니다. 비트코인 블록 확정 여부는 `ots verify` 로 따로 봅니다.
- 숫자를 합친 종합 점수는 일부러 두지 않습니다.

## 주장↔영수증 대조(측정 전용)
에이전트가 답을 마칠 때(Claude Code `Stop` 훅) 마지막 답변에서 "12 passed", "src/x.py 수리했습니다", "검증했습니다", "완료" 같은 문장을 **규칙으로** 뽑아 **같은 세션의 영수증**과 맞춰 봅니다.

| 문장 종류 | supported(근거 있음) | unsupported(근거 없음) | unknown(판단 보류) |
| --- | --- | --- | --- |
| 테스트("N passed", "테스트 N개 통과") | 세션 안에 결과 요약 줄이 남은 테스트 실행이 있고, N 을 말했다면 어느 실행의 통과 수와 같음 | 테스트 실행 흔적 없음, 또는 말한 N 이 어느 실행과도 다름 | 요약 줄 없는 실행뿐(예: `pytest --version`·`--collect-only`), 또는 마지막 실행 요약에 실패·오류가 있음 |
| 수리·구축("수리했", "fixed", "구현했") | 지목한 파일이 Edit/Write 됨 | 지목한 파일에 닿은 흔적 없음(지목 없으면 편집 0) | 읽기만 함, 또는 파일 지목 없이 편집만 있음 |
| 검증("검증", "verified") | 지목한 파일에 닿음 / 지목 없으면 요약 줄이 남은 테스트 실행 있음 | 지목한 파일에 닿지 않음 | 지목도 요약 줄 있는 테스트도 없음 |
| 완료("완료", "done") | 지목한 파일에 닿음 | 지목한 파일에 닿지 않음 | 지목 없음 |
| 검수("검수했", "reviewed") | — | — | 항상(영수증에 검수 흔적이 없음) |
| 부정·유보("못했", "미검증", "대기", "not verified") | — | — | 항상, 적중률 계산에서 빠짐 |

- 같은 세션에 **여러 에이전트(본 에이전트 + 하위 에이전트)의 흔적이 섞이면 unknown** 입니다 — 누구의 일인지 가를 수 없기 때문입니다.
- **차단하지 않습니다.** 막으면 표현을 바꿔 피하게 되고 셀 수가 없어집니다. 항상 종료 코드 0, 실패하면 stderr 에 한 줄.
- strict 모드에서는 문장 대신 HMAC 만 남깁니다.
- 한계: 규칙 기반이라 오탐·누락이 있습니다. 영수증에는 명령어 원문이 없어서 "어떤 테스트 파일을 돌렸는지" 는 대조하지 못하고 "테스트를 돌렸는지와 그 통과 수" 까지만 봅니다. 하위 에이전트의 최종 보고(SubagentStop)는 대조하지 않습니다.

## 보안 기록이 남지 않도록 — 무엇을 기록하고 무엇을 절대 기록하지 않는가
| 절대 기록하지 않음 | 파일 내용, 명령어 원문, 도구 출력 원문, 대화 원문, 비밀키 |
| --- | --- |
| **이름도 숨김**(HMAC만) | strict(기본): 모든 경로. normal: `.env`, `*.pem`, `*.key`, `*secret*`, `*token*`, `*password*`, `.ssh/`, `.aws/` 등 기본 목록 + 직접 지정한 `.risealignore` 패턴 |
| **열쇠가 있어야만 대조 가능** | 명령어·세션·하위 에이전트 id 는 비밀 키(pepper)로 만든 HMAC — 짧은 비밀번호도 추측으로 알아낼 수 없음 |
| **숫자만 기록** | 테스트 실행으로 보이는 명령의 `test` 표시와 마지막 요약 줄의 통과·실패 개수 |
| **그대로 기록**(normal 만) | 민감하지 않은 프로젝트 안 파일 경로와 그 지문(SHA-256), 주장 문장 앞 200자 |

### strict(기본) 와 normal 의 차이
| | strict(`ri-seal init`) | normal(`ri-seal init --privacy normal`) |
| --- | --- | --- |
| 영수증의 경로 | 전부 HMAC, 파일 지문도 HMAC | 민감해 보이지 않으면 그대로 |
| 봉인 대상 이름 | `hmac:…` (제3자는 이름 대신 문서의 SHA-256 으로 확인) | 그대로 |
| 주장 대조 기록 | 문장은 HMAC, 파일은 개수만 | 문장 앞 200자와 파일 이름 |
| `status --details` | 줄 번호로만 추적 | 줄 번호 + 열어 보면 파일 이름이 보임 |
| 권장 | 기록이나 묶음을 남에게 보여 줄 가능성이 있을 때(기본) | 혼자 쓰는 프로젝트 |

- 0.1 로 만든 프로젝트는 설정이 그대로입니다.
- 봉인할 때 비밀처럼 보이는 파일은 자동으로 빠지고 알려 줍니다(`--allow-sensitive` 로만 포함).
- 기록 폴더 `.riseal/` 는 본인만 읽을 수 있게(700) 만들어지고 영수증·봉인 파일은 600 입니다. 서명 키와 pepper 는 프로젝트 밖 `~/.riseal/keys/` 에 0600 으로 둡니다.

## 한계와 전제(꼭 읽어 주세요)
- **봉인하지 않은 최근 기록은 보호되지 않습니다.** 마지막 봉인 이후의 영수증은 지워도 드러나지 않습니다. 하루 1번 이상 `seal` 하세요.
- **봉인 행 자체를 꼬리에서 잘라내는 것은 로컬 `verify` 가 못 잡습니다**(키가 없어도 가능). 밖에 둔 `export` 사본의 봉인 수와 비교하거나 `verify --expect-seals N` 으로 확인해야 드러납니다.
- **앵커 행은 서명되지 않습니다.** `verify` 는 영수증이 '이 봉인에 대한 것'인지만 확인하고, 진위는 `ots verify`·`openssl ts -verify` 로 따로 확인합니다.
- **에이전트도 같은 사용자 권한으로 돕니다.** 에이전트가 마음먹으면 `~/.riseal/keys` 의 키를 읽어 기록과 도장을 통째로 다시 만들 수 있습니다. 아래 세 가지는 그 위험을 **줄이는** 장치이지 완전히 막는 장치가 아닙니다.
  1. **`ri-seal anchor` 를 매일 실행하고, 2번과 함께** — 비트코인·타임스탬프 기관의 시각 증명은 키가 있어도 과거로 다시 만들 수 없습니다. 다만 증명 파일이 같은 컴퓨터에 있으면 함께 지워질 수 있으므로 외부 사본과 함께해야 효과가 있습니다.
  2. **`export` 묶음을 에이전트가 닿지 않는 곳(다른 기기·메일)에 보관** — 나중에 다시 만든 기록과 비교됩니다.
  3. **에이전트가 키 폴더를 읽지 못하게 설정** — Claude Code 라면 프로젝트 설정의 `permissions.deny` 에 `Read(~/.riseal/**)` 등을 추가하세요. 설정은 우회 가능성이 있어 보조 장치입니다.
- **주장 대조 기록은 봉인에 묶이지 않습니다(0.2 한계).** `.riseal/claims.jsonl` 은 줄마다 앞줄 지문을 품는 해시 사슬이지만 봉인 대상이 아니어서, 통째로 다시 쓰면 `verify` 가 잡지 못합니다. `status` 의 숫자도 같은 컴퓨터의 파일을 센 값입니다.
- **자동 기록은 Claude Code 훅만 있습니다.** 다른 에이전트의 작업은 영수증으로 자동 기록되지 않습니다.
- **제3자는 공개키 지문을 따로 확인해야 합니다.** `verify` 가 출력하는 `pubkey_sha256` 을 발행자가 자기 웹사이트·GitHub 에 올린 값과 비교해야 위조 묶음을 걸러냅니다.
- macOS·Linux 전용입니다(Windows 미지원).

## 명령 요약
| 명령 | 하는 일 |

| `ri-seal install-claude-hook [--shared] [--no-claim-hook] [--dry-run]` | 로컬 설정(`settings.local.json`, 기본)에 기록 훅(PostToolUse)과 주장 대조 훅(Stop) 추가, 바뀔 내용을 먼저 출력. `--shared` 는 팀 공유 `settings.json` 에 경로 없는 명령으로. 처음 원본은 `.bak` 보관 |
| `ri-seal uninstall-claude-hook [--shared] [--dry-run]` | 위에서 설치한 항목만 제거, 다른 훅 보존, 바뀔 내용을 먼저 출력 |

## 릴리스 확인
릴리스마다 sdist·wheel 의 `SHA256SUMS` 와, 그 파일들을 ri-seal 자신으로 봉인·시각 고정한 검증 묶음을 함께 올립니다(`scripts/release.sh`). 받은 파일은 `shasum -a 256 -c SHA256SUMS` 로, 묶음은 `ri-seal --dir <폴더> verify` 로 확인하고 아래 공개키 지문과 대조하세요.

## 루트인사이드 공개키 지문(대역외 대조용)
루트인사이드 자사 봉인(https://www.rootinsidegroup.com/trust)의 Ed25519 공개키 지문 — 웹사이트에 적힌 값과 **이 저장소의 값이 같아야** 합니다(둘 중 하나가 바뀌면 키가 교체·변조된 것).
```
sha256(raw 32-byte key) = 29b8c0462adbc700b147b634e18021fb58e34478272be5a56547d7aa4e7889d8
```
확인: `openssl base64 -d -in pubkey.pem | tail -c 32 | shasum -a 256` (macOS LibreSSL·Linux OpenSSL 공통).
